# Flow: sync of managed files

Used when `status` says `next: sync`: `removals.decisions` lists managed files whose source was removed in the parent template while the local file is changed or was deliberately accepted (`reason`: `source_removed_local_differs` or `source_removed_local_changed`); `sync.decisions` lists managed files whose current template and local file differ and whose stored source/local hash pair does not fit (`reason`: `no_accepted_pair`, `source_changed`, `local_changed` or `both_changed`). Files that are only missing or identical (with a missing or stale pair) are handled by the skeleton flow without a dialogue; deviations whose pair still fits (`accepted`) are not asked about again. Python never asks; this flow does.

Per decision (content or removal question), one file at a time, in small guided steps, in the operator language (see `../references/operator-language.md`):

1. Show only the file path and state that differences exist, or for a removal question that its source was removed in the parent template. Do not read source_file or local_file to explain the change. Do not show file contents, text excerpts, a diff or a content summary. Then ask for the decision below.
2. Ask explicitly with the host's question tool, or one targeted question per message without it, the real decision "Keep local file" or "Adopt template" for a content question, and "Keep local file" or "Delete local file" for a removal question (in the operator language). A preselection, silence, a cancelled or rejected question is not a decision: nothing is written or stored, the file stays as it is, and the flow waits until the entry is called again.
3. Apply exactly the chosen decision for the shown pair: `python3 -B "<helper>" sync --target "<folder>" --plugin <plugin> --decision keep|adopt --path "<path>" --source-hash <source_hash> --local-hash <local_hash>` for a content question, or `--decision keep|delete --path "<path>" --source-hash removed --local-hash <local_hash>` for a removal question, with the hashes from the last `status`. `keep` keeps the current local bytes and records both current hashes; `adopt` replaces only this file with the template (its mode is kept), verifies it and records both hashes. For a removal question `keep` keeps the local file and records `source_hash: null` with the current `local_hash`, so an unchanged repetition does not ask again while a later local change does; `delete` removes only this verified file, its lock entry and then its empty parent folders (`removed.files`, `removed.directories`). Only the explicitly chosen file is touched; no file content, excerpt, diff or summary is ever shown.
4. Check `ok` and the exit code. On `ok: false` or exit 1 (for example `stale_decision`: the files changed after they were shown) report the concrete reason and the partial changes that actually happened (`changed.file`, `changed.lock`, `created.directories`, `removed.*`) and stop; do not retry silently. A stale decision is not applied: run `status` again and ask anew for the new pair.
5. On success run `status` again (see `entry.md`); continue with the next open decision if there is one. Accepted deviations do not trigger the flow again and never mean `matches_template`.
