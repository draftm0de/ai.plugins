# Flow: plugin configuration

Used when `status` says `next: configure` (language and skeleton are done, no plugin.json). Stay in this call and in this folder; do not send the person to another command or folder.

1. Follow `../../_shared/references/workflows.md` for the required inputs, the licensing decision and the `plugin-create --skeleton` helper call with `--root "<folder>"`. The operator language counts as the established conversation language (do not ask it again). This flow runs only when plugin.json is absent.
2. Required facts (never invent or dummy-fill them): technical and display name, description, publisher, documentation languages, license decision (or explicit deferral), the GitHub origin of the checkout and the **explicitly selected** marketplace checkout. Never change another marketplace without that selection.
   - Guided dialogue, identical on the first call, after an aborted dialogue, after every answer and after a tool error: every call of this entry re-reads `status` and this flow and applies it from the start. Do not summarize all open facts as a text list, do not offer a free-text "write me the details" form and do not ask which dialogue form the person prefers.
   - Take over only facts the person explicitly answered in the current conversation. A question that was cancelled, dismissed, rejected by the host or left unanswered is not an answer and stays open. Answers given so far live only in the chat: no new persistence and no configuration write before step 4.
   - Ask the next open question, or one small coherent group, with the host's question tool (for example `AskUserQuestion` with its actual schema and limits). Without such a tool, or for free facts without a meaningful choice (name, description, rights holder, paths), ask exactly one targeted text question per message and wait.
   - Marketplace: a suggestion is never a selection. Even with a single candidate ask for explicit confirmation of the concrete path as a real decision ("Use this checkout" / "Choose another checkout"); never add a filler option, and never adopt a candidate because of a suggestion, a preselection or a tool error. For another checkout ask for the path with one targeted question and confirm it. A path the person already confirmed explicitly in this conversation is not asked again.
   - A schema error or rejection of a question call means that no question in it was answered. Ask the valid questions again, separately and correctly formed; the duty of an explicit selection stays, whatever the generic tool error says.
   - Only an explicit request of the person for a complete list or a text mode may change this form.
   - Missing choices are asked first, one step at a time; only after a deliberate postponement or cancellation by the person respect it: state briefly that configuration is paused, keep everything already created, and wait. Do not ask again on your own; the next call of this entry continues with the next open question.
3. A missing external prerequisite that no answer can fix (for example no Git checkout with a GitHub `origin`) is named once, keeping everything already created (language, skeleton, lock, `.git`, `.idea`); then wait. This rule never replaces asking for a missing selection or fact in step 2, and it is not a failure of the skeleton; never roll anything back, create or set remotes or repositories, or publish.
4. Run the generator only after all required facts are answered and the marketplace checkout is explicitly confirmed. Until then nothing is written for the configuration.
5. If the generator refuses because a skeleton file deviates from the template (also when the person deliberately kept the local file in the sync flow), report it openly and stop: nothing is replaced and neither this folder nor the marketplace was changed. Deviations are only resolved by the sync flow.
6. Judge the result by the generator's own answer, which has `action`, `changed`, `checks` and a prose `next` but no `ok`: success means exit 0 **and** `checks.status == "passed"` (`checks.licensing` shows whether the license is implemented, deferred or inconsistent). On a non-zero exit or `needs_attention`, report the failing entries under `checks` and the files actually listed in `changed`, include the generator's `next` text, and stop; do not say "ready", do not derive success from a plugin.json that now exists, and do not run `status` to declare it done. A `ready` from a later `status` stays only "no automatic setup flow open" while this problem is unresolved.
7. After a really successful configuration run `status` again (see SKILL.md); then report open decisions (for example a deferred license) and pending domain implementation. Do not publish, install or implement anything.

## Creation rules retained by this internal flow

The internal `plugin-create --skeleton` Python operation creates only a nonfunctional scaffold. Never offer skill import, a source skill path or a creation mode. Reuse confirmed facts; never invent domain capabilities or license terms. Documentation languages are independent of the saved operator language. Do not present CLI flags as required user input.

Before generator writes, resolve the license explicitly: reuse an unambiguous existing license or session decision, otherwise ask for a license or explicit deferral and wait. Silence is not deferral. Preserve existing license bytes and clarify conflicts. For MIT, confirm copyright year and rights holder (publisher is not automatically rights holder); pass `--license MIT`, `--copyright-year` and `--copyright-holder`. For another license, use a confirmed identifier and complete `--license-file`. Use `--license deferred` only after explicit deferral, and report it as unresolved. Check `checks.licensing` against the files actually created.

Preserve existing prose and resolve reported documentation gaps within the creation request. Separate structural checks, documentation, licensing, pending domain implementation and tests/host checks actually run in the report. A `needs_attention` result is incomplete creation, not success. Never execute target code as part of these checks.
